# Persistent APK signing — Codex Companion

**Status:** Workflow configured. One-time GitHub Actions secret provisioning is required before GitHub can produce a permanently signed APK. No private key is stored in this repository.

## Why it changed
Earlier GitHub Actions runs relied on the runner's autogenerated debug keystore, producing a different signing identity per run. Android will not accept an APK signed with a different certificate as an in-place update.

## Private key and GitHub setup
A unique PKCS#12 signing key was generated outside this public repository and delivered to the user as a private signing kit. Retain an offline backup. It must **never** be committed.

Alias: `codexcompanion`

Expected signing certificate SHA-256:
`37:D7:92:3B:C1:49:50:6E:0D:5F:BE:D5:29:8F:B4:45:6B:F1:76:F7:96:34:17:0F:1B:74:A5:24:1F:3B:68:EB`

Required repository secrets (Settings → Secrets and variables → Actions):
- `CODEX_SIGNING_KEYSTORE_BASE64`: base64 of the `.p12` key file (no newlines)
- `CODEX_SIGNING_STORE_PASSWORD`: PKCS12 store password
- `CODEX_SIGNING_KEY_ALIAS`: `codexcompanion`
- `CODEX_SIGNING_KEY_PASSWORD`: matching private key password

The private kit contains a `setup-github-secrets.sh` script to upload secrets securely using `gh secret set` after `gh auth login` on the user's own phone.

## Build
Once secrets are configured:
```bash
gh workflow run build-edge-only.yml --repo kunokun12/Codex-Edge-Glow --ref feature/companion-persistent-signing
```
Download the artifact named `codex-companion-persistent-debug-apk`. GitHub verifies a v2 signature before uploading it.

## Migration
The installed Companion v2.2/v2.3 APKs were signed by ephemeral GitHub debug keys. Their private keystores were not preserved. Thus **one uninstall/reinstall** is required to switch to the new persistent signing identity, unless the original installed key can be recovered separately. Uninstall clears Companion app data and its accessibility/overlay permissions. It does not remove the old native helper.

Future APKs built using the same persistent key can use `adb install -r` as long as the new versionCode is greater than or equal to the installed versionCode, with normal Android signing checks.

Keep the signing key private and backed up. This is a development-only, debuggable application that still requires the Android MCP's `run-as` bridge; never distribute a debug build as a production security model.
