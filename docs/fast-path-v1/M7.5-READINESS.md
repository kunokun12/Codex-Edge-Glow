# M7.5 readiness decision

**Decision: NOT READY for live device testing or execution.** The current work did not install an APK, enable an Accessibility service, modify Android settings, restart a service/device, invoke a live UI action, or send `route.execute` to a real app.

## Gates still open

1. M1 owner approval of a versioned UI fingerprint producer and `snapshot.sha256` semantics; candidate v2 is not authoritative.
2. Owner-controlled production public-key enrollment and an approved root-signed keyset rotation implementation. The shipped trust-anchor list is empty.
3. A separately approved observer binary/provenance and a demonstrated Android process boundary. The candidate component is in a separate app process but shares package, signing identity, and UID; no API/device process test was run.
4. A trustworthy monotonic anti-rollback anchor and recovery procedure. SQLite transactionality and `allowBackup=false` are not anti-rollback protection against restoring a consistent older app-data image.
5. Exact M1 typed handlers for `route.execute`, `evidence.capture`, and `route.verify`. The current receiver keeps these paths `UNIMPLEMENTED` rather than synthesizing evidence or success.
6. API 26 cryptographic provider and SQLite durability validation on an actual supported Android runtime, plus current-device read-only compatibility checks.
7. Exact-commit regression CI and reproducible artifact provenance. A successful APK compile is necessary but does not approve the observer or enable execution.

## Allowed next validation after review

After the relevant owners approve the protocol amendment and observer provenance, a separately authorized read-only installation-free test may validate manifest/package metadata and the disabled observer component. Enabling Accessibility or running any route requires separate explicit authorization. Live execution remains blocked until all authorization, rollback, at-most-once, and independent-verification gates close.
